# Prompt

Our GitLab pipeline takes ~20 minutes and the stages serialize everything. Here is the current `.gitlab-ci.yml`:

```yaml
stages: [build, test, deploy]

build-frontend:
  stage: build
  script: [npm ci, npm run build]
  artifacts: { paths: [dist/] }

build-backend:
  stage: build
  script: [mix deps.get, mix compile]
  artifacts: { paths: [_build/] }

lint:
  stage: build
  script: [npm run lint]

test-frontend:
  stage: test
  script: [npm test]

test-backend:
  stage: test
  script: [mix test]

build-matrix:
  stage: build
  parallel:
    matrix:
      - OS: [ubuntu, alpine]
        NODE: [18, 20]
  script: [make build OS=$OS NODE=$NODE]
  artifacts: { paths: [out/] }

test-matrix:
  stage: test
  parallel:
    matrix:
      - OS: [ubuntu, alpine]
        NODE: [18, 20]
  script: [make test OS=$OS NODE=$NODE]
```

test-frontend only needs build-frontend, test-backend only needs build-backend, and each test-matrix job should pair with the build-matrix job having the same OS/NODE. lint has no real dependency on anything. Rewrite the YAML with DAG so the pipeline runs as fast as possible, and explain the changes.

# Criteria

- [ ] test-frontend gains `needs: [build-frontend]` and test-backend gains `needs: [build-backend]` so each test starts when its own build finishes, not when both builds finish
- [ ] lint gets `needs: []` (immediate start, no dependency)
- [ ] test-matrix maps 1:1 to its build-matrix counterpart via `needs` with `$[[ matrix.OS ]]` / `$[[ matrix.NODE ]]` expressions (and notes the GitLab 17+ requirement) rather than manually listing all four build jobs
- [ ] Addresses artifact download: explicitly keeps artifacts flowing to dependent jobs (`artifacts: true` in needs, or notes that needs skips non-listed jobs' artifacts)
- [ ] Keeps a `stages:` declaration in the rewritten file and states the total job count generated by the matrices (4 + 4 = 8, within the 200-job limit)
- [ ] Response does NOT "optimize" by removing `parallel:matrix` / merging matrix jobs into one sequential job, and does not propose switching to a different CI system
